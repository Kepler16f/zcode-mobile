# Android 版本与安装包交付

每次用户请求打包时先询问版本号，用户已明确指定的版本直接使用。Gradle 打包任务要求显式传入三段数字版本号，并根据版本号生成递增的 Android versionCode。自动化 CI 传入固定测试版本，不访问用户下载目录。

本地 Windows 构建成功后，将 APK 临时复制到系统下载目录，校验 SHA-256，一致后原子替换目标文件，再删除下载目录中匹配 `aZCode-<数字版本>.apk` 的旧版本文件。失败时保留旧安装包并报告失败；不删除其他应用、其他扩展名或目录。构建失败不运行交付清理。

验收：缺少版本或版本格式错误时禁止打包；成功包的应用版本、文件名和下载文件内容一致；旧版本清理、同名文件替换、其他文件保留、复制失败保留旧包；CI 不交付到下载目录。

包体积优化：Android 中自检页和主界面共用 assets/ui 下的 sql.js/WASM；自检源码在浏览器开发环境中仍独立使用 dist 资源。运行时同步采用 Sync，移除过期副本。UI 旧哈希资源清理失败应中断构建，防止混入新包。评估 APK 体积时区分 debug/release、有效压缩内容及增量 ZIP 的空闲区；交付构建可使用 --rerun-tasks 消除旧打包状态，并验证签名兼容性。

## 交付前的重压重签（0.10.0）

AGP 8.13 的 debug 构建对资源用最快压缩等级（BEST_SPEED）：同一份 dist-ui，entry.js 7.8 MB 正文
在等级 1 下压成 2.48 MB、等级 9 只要 2.06 MB；APK 任务上的 `compressionLevel` 属性在 8.13.2 上
不生效（由构建类型内部决定）。因此在 APK 打出来之后重压一次：

```text
packageDebug → 重压条目（等级 9）→ zipalign -p -f 4 → apksigner 用同一 keystore 重新签名 → 发布
```

- **内容不变**：条目集合、每个条目的 CRC/大小/压缩方式逐条比对一致，只有压缩字节变了
  （`mobile-runtime/build/verify-repacked-apk.mjs`）。
- **证书不变**：用同一个 keystore 重新签名，证书 SHA-256 与此前版本一致，手机上可直接覆盖安装。
- **收益**：0.10.0 实测 17,138,665 B → 12,888,672 B（省 4.25 MB），比 0.9.2 的 14,652,462 B
  还小 1.76 MB，而这一版多了会话分叉、子代理后台、Git 面板与文件监视四项能力。
- 只对 debug 变体做；release 变体本身就使用较高等级。
