# 移动端文件监视服务

桌面用 node:fs 的 watch（内核事件）。Android 没有 fs.watch：SAF 树与本地盘都拿不到 inotify，
所以端侧实现为**轮询签名**：按固定间隔取一次目录快照（名字 + mtime + 大小），与上一份快照
比对，变化才发事件。事件形状与桌面一致：`{ dirPath, changedPath? }`；只有确定的变化路径只有一个时
才带 `changedPath`，否则调用方按保守刷新处理。

## 所有者与时序

```text
UI watch(id) -> 监视器（id -> 快照）
                -> 每 2.5s 扫描一次 -> 签名比对 -> 150ms 防抖 -> onDynamicChange(id)
页面不可见 -> 停轮询；回到前台 -> 补扫一次
```

- 快照与事件都由同一个监视器实例持有；`unwatch` 与 `disposeAll` 释放定时器与事件发射器。
- 订阅晚于 `watch` 返回时，桌面允许 watcher 已失效（返回空事件而不抛错）；端侧同纪律。

## 平台代价（如实记录，不得当作免费）

- 本地盘：一次 `readdir` + 一次批量 `statMany`（1 次 JNI 往返）。原生桥没有 `statMany` 时
  退化为逐个 `statSync`（N 次往返），仍可用但更慢。
- SAF 树（`/mnt/...`）：一次 `readdir` + 目录自身 mtime。子文件**内容**改动检测不到
  （SAF 单次 stat 约 30-40 ms，逐个 stat 会直接卡住主线程），只报告增删改名。
- 递归监视有上限（200 目录 / 5000 条目），超限后只比较已扫描部分，事件省略 `changedPath`。
- 页面不可见时停止轮询；后台扫树只耗电发热，正是此前「用一会儿就卡」的来源之一。

## 失败语义

- 监视不存在的路径或非目录：像桌面 `fs.watch` 一样当场抛错（`无法监视目录 <path>`），
  不返回一个永远不会触发的 watcher id。
- 扫描过程中目录被删或无权读取：跳过该目录，本轮不报故障；目录自身的签名记为 `missing`。
- 失效 watcher id 的事件订阅：返回空事件，不抛错打死订阅链路。

## 验收

`mobile-runtime/build/file-watcher-smoke.mjs`（12 项）：新增/内容变化/删除触发事件；单一变化带
`changedPath`，多变化合并为一次保守事件；无变化不发事件；`unwatch` 后不再发；失效 id 不抛错；
不存在的目录与相对路径如实报错。
