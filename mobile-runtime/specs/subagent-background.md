# 移动端子代理后台执行

## 范围

移动端子代理是**同进程内**执行的：`mobile-runtime/ui/skills-subagents.ts` 拥有子代理的模型循环，
`mobile-runtime/ui/agent.ts` 拥有子会话（`mobile-subagent-*` sessionId）、子代理行与持久化。
本 spec 补齐两条桌面已有、移动端缺失的能力：后台执行与跨轮续接（resume）。

## 行为

- `Agent` 工具新增 `run_in_background`（boolean）。为 true 时，父轮的这次工具调用**立即**返回
  「子代理已在后台启动」，父轮继续自己的模型循环，不等待子代理结束。
- profile 自身声明 `background: true` 时默认后台运行；调用方显式传 `run_in_background: false` 可覆盖。
- 后台子代理仍受父轮的**执行模式**约束（计划模式不能写），工具调用仍走父 Agent 的
  Hook、工作区授权与人工审批入口——不允许直接调用底层执行器绕过父轮闸门。
- 后台子代理有自己的取消闸。取消来源：父轮本轮被停止、用户对父会话点「停止」、
  工作区被释放、全局释放。取消等价于前台路径的 abort：行落 cancelled，不伪造完成。
- 后台子代理的完成/失败/取消**回填父会话**：父会话里那条 `subagent` 行从 running 变为
  success/failed/cancelled，并带上结束时间；子会话正文与用量照旧落盘。
- 审批交互仍然挂在父会话上（用户看得到、答得了）。父轮已经收口时，审批的取消闸改由
  后台子代理自己的取消闸兜底，不能出现「无人应答的永久挂起」。

## 续接（resume）

- `Agent` 工具新增 `resume`（string）：上一次子代理的 agentId。给了就沿用那个子代理继续，
  不新开一个。
- 续接沿用**同一个子会话**（子会话 id 不变），在该子会话里开新的一轮；父会话另起一行
  `subagent` 指向同一个子会话，两轮各自可追溯。
- 续接沿用上一次的 transcript：system 提示按当前 profile 与执行模式重建，其余历史原地保留，
  新的输入接在后面。子代理因此记得上一次的任务**和上一次的结论**。
- transcript 的所有者是 Agent 服务（进程内）。端侧没有把子代理 transcript 落盘的形状，
  因此**进程重启后不可续接**：续接请求会带「该子代理已不在本次运行中」的具体原因报错，
  不会新开一个假装是续接的子代理。
- 续接必须属于同一工作区；跨工作区续接明确拒绝。
- 续接的子代理类型必须与上一次一致，否则报错（不能把 A 的历史接到 B 上）。

## 状态所有者与事件顺序

```text
父轮: Agent(run_in_background=true)
  → 子会话创建（onStarted）→ 父会话插入 subagent 行(running)
  → 父轮工具调用返回「已启动」→ 父轮继续
  → [后台] 子代理模型循环 → 工具调用 → 父轮 Hook/授权/审批 → 结果回灌子 transcript
  → 子代理结束 → 子会话收口 → 父会话 subagent 行更新(success/failed/cancelled) → 两边落盘
```

- 后台任务登记在 Agent 服务内（按父会话 id 归组），唯一所有者是 Agent 服务；
  技能/子代理设置服务不持有运行状态。
- 幂等边界：一次 `Agent` 工具调用只登记一个后台任务；子代理 id 由本次调用生成，
- **跨进程续接**：子会话的模型 transcript（system + user + assistant/tool 往返）与子会话一起
  落盘，进程重启后仍可用同一个 `agentId` 续接；附件（base64 图片）不落盘——会话库不是
  附件仓库，带进去会把库撑成几倍。续接时若库里的 transcript 不存在，如实报错，不新开一个
  假装是续接的子代理。
  重复调用互不影响。

## 失败语义

- profile 仍带独立 MCP server：明确报错（独立 MCP 运行时未接入），不静默忽略配置。
- 后台子代理自身失败（模型报错、工具被拒、超轮次）：按失败回填父会话，父轮不受影响。
- 后台子代理在父轮收口后需要审批，而用户一直不答：随取消闸结束（停止/释放）后落 cancelled。

## 验收

- `run_in_background=true` 的 Agent 调用立即返回，父轮继续推进；
- 后台子代理最终状态回填父会话的 subagent 行；
- 父轮停止能取消后台子代理（行落 cancelled）；
- 后台子代理的工具调用仍受父轮模式与审批约束（计划模式下的写操作被拒）；
- 前台子代理路径逐字不变（不传 run_in_background / resume 时行为完全一致）。
- 续接沿用同一个子会话与上一次的 transcript（含上一次结论）；续接不存在的 agentId 时如实报错。
