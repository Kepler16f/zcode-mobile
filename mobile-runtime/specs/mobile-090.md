# 0.9.0平台能力与迁移

- 移动UI的Shiki模块图统一从Streamdown/diff共同使用的依赖实例解析，保留全部语言与主题；不通过删除输出chunk减包，桌面依赖不改。构建metafile校验语言模块只来自一个根。
- 复制Web CSS时同步解析本地url依赖，重写为移动UI目录下的相对URL；资源缺失或越过Web产物根时构建失败。字体、公式、高亮需用真实浏览器验证。
- 高亮Worker必须是同一splitting构建中的独立入口；编译时将Vite的源码URL转换为产物相对URL。主界面与Worker共享语法chunk，不能把不存在的TypeScript URL交给浏览器或把高亮回退到主线程。

- 复用桌面Memory路径、MEMORY.md索引和提示规则；开关关闭不注入记忆，开启后会话可用Read/Write真实持久化，设置页读取同一目录。
- 活动与Start Plan复用正式客户端配置、场景、订阅、账号凭据及额度服务；移动请求通过原生异步HTTP桥，错误可见，不能制造活动、领取成功或额度。
- SAF迁移仅根据已持久授权的准确URI解析且实际可读的本地目录。保留旧URI和挂载名作为别名，旧项目/会话引用继续有效，文件操作与Git使用对应本地路径。不能把云盘或无法验证的树猜成sdcard目录。
- 子会话不进入任务索引；已有索引中的旧子会话隐藏。恢复索引时清除无运行者的running/审批状态。
- 子会话虽由父轮驱动而没有独立run句柄，正文仍复用5秒合并检查点；切后台保存两者，重启不恢复虚构的子代理运行者。
- 每轮保存请求实际modelId/providerId与token，模型切换后历史不改归属。
- 验收包含竖屏抽屉与横屏恢复、开关期间主线程响应、模型A/B统计、子会话重启与隐藏、记忆跨会话开关、活动原生网络、旧SAF路径Git/历史连续性。
