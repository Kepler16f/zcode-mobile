# 移动端运行时可靠性与权限

## 状态所有者与顺序

移动 Agent 是会话行、执行状态与工具调用历史的唯一所有者；UI 只消费协议快照和增量。执行顺序为：

```text
输入 → Agent 接纳 → 保存用户行 → 模型请求 → 钩子改写 → 按最终动作检查权限
     → 保存工具开始 → 执行副作用 → 保存工具结果 → 模型继续 → 保存终态
                                      ↘ 中断后恢复为 interrupted，不自动重跑
```

流式正文按有界间隔保存，用户离开页面时尽力刷新。每个工具执行前后立即落盘；恢复时未完成工具必须显示中断状态，不能推断其副作用未发生，也不能自动重复执行。保存失败只报告诊断，不把内存中成功的执行伪装成持久化成功。

## 模型历史与附件

持久化的时间线是跨轮历史的来源；完整的工具调用与结果按协议顺序进入后续请求，压缩覆盖的行不能重复送入。旧会话缺少工具输出时保留现有文本，不伪造结果。附件在命令、排队、时间线及模型请求之间保持引用；无法读取或模型格式不支持时显式失败，不能接受后静默丢弃。

## 计划模式

计划模式禁止无审批的文件或仓库写入。按最终工具名和参数判断，未知的 Fetch/Git 动作默认拒绝；只读 Fetch、只读 Git 可继续；Bash 维持人工审批。PreToolUse 改写参数后必须再次检查，不可被钩子允许覆盖。

## 验收

覆盖跨轮工具结果、流中检查点与重启恢复、工具前后中断、计划模式写入和钩子改写、附件发送及排队、正常只读调用。桌面 continuous 和移动会话现有协议帧序列不得回归。
