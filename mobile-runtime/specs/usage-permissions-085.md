# 0.8.5 用量、上下文与权限回归

## 用户场景

- 设置中的应用用量页无法读取统计。
- 使用或静置后所有按钮失去响应，后台仍可能运行。
- 上下文用量似乎只随请求次数增长。
- 切换完全访问以后，新到达的工具调用仍要求审批。

## 修复与验证边界

1. OpenAI兼容流请求声明 `stream_options.include_usage`；Anthropic兼容协议将缓存读取及缓存创建输入计入完整输入用量。后续局部usage帧不覆盖前面已取得的输入总量。
2. 上下文占用使用最近一次完整请求输入加本次输出，缺失usage时按消息内容估算；累计统计独立累加每次请求真实token。两者均不按请求次数计算。压缩成功后重算占用，恢复会话保留水位。
3. 设置统计从独立的小型投影读取。旧版记录按64K字符分块迁移，每块让出事件循环，避免将多MB会话整行送过Android CursorWindow。统计不沿用侧栏200会话上限，聚合不再为每轮重新扫描全部历史。原始会话不删除。
4. 移动端工具栏模式变化立即通过配置CAS通知运行时。正在等待的权限请求及随后新发起的主/子代理工具调用均消费新模式。自动模式放行只允许本次，不写入用户“始终允许”记忆。计划限制、工具白名单和Hook拒绝仍生效。
5. 关闭原生SQLite写入及辅助查询语句，清理已完成审批留下的AbortSignal监听器。对于没有可见弹层持有的残留 `body:pointer-events:none`，等待退场后恢复输入；真实审批、菜单和可见弹层继续保留锁。自检M13包含恢复记录。

## 验收

最终检查还移除了启动时的全历史统计探针：过去该探针失败后将 `usageStatsService` 放入 `degraded`，客户端再把已注册的服务替换为不可用面，导致统计页无法通过刷新恢复。现在只在打开统计页时读取，一次读取失败不会禁用服务，重试恢复有专项验证。

- 对话协议：覆盖运行中切模式、切换后新的Write/Bash调用、已经挂起的审批、token统计及压缩。
- 设置真实界面：配置自定义供应商，经真实Provider解析和本地模拟网关完成3轮，应用用量页显示177 token；趋势图和模型图加载成功。
- 存储：205个旧会话、多MB含emoji正文、迁移期间UI心跳、投影重读和并发迁移。
- 触摸：遗留锁恢复、按钮实际可点、真实审批保留、关闭菜单释放锁。

未连接Android真机，尚不能确认用户设备的静置冻结已全部消除。以上触摸锁是可复现并有恢复验证的故障类型，不能据此认定所有卡死均为同一原因。旧版本供应商未回传、应用也未保存的历史token无法准确反推。
