# 移动端上下文压缩

## 参照

桌面端按"助手起头的完整轮次"切段，按轮次生成摘要，保留近期原文，原始会话仍留在时间线里
（`zcode/apps/zcode-cli/packages/core/src/compact/`：policy.ts 定阈值与熔断，
rounds.ts / compact-selection.ts 定切段与保留，prompt.ts 定摘要提示词）。
端侧对齐这套语义，并按手机端的约束补两件事：阈值要算得进模型窗口，失败必须说人话。

## 切段与保留

摘要边界只落在完整轮次之间：同一轮的"用户输入 / 助手正文 / 工具调用 / 工具回包"要么整段进摘要，
要么整段逐字保留。边界切在轮次中间会留下没有回包的 tool_calls，网关会直接拒。

保留区按 token 预算从最近一轮往回取整轮（默认模型窗口的 20%，下限 1024、上限 16000），
至少保留最近一轮。时间线行一条不删——展示层全量回放，压缩只改"送进模型的历史"。

## 分段摘要（不丢历史）

早期段装不进一次摘要请求时，桌面端会把更早的轮次丢掉再重试（`selectCompactEntriesAfterPromptTooLong`）。
端侧不这么做：丢掉更早的轮次等于悄悄丢历史。端侧改成**分段摘要**——按整轮切成若干段，
一段一段压，前一段的摘要作为前缀带进后一段，最后一段的摘要就是最终摘要。
单轮正文大到一段都装不下时明确失败，不截尾正文，也不推进摘要覆盖水位；
系统提示、上一段摘要、末尾指令不许被截。

## 阈值、熔断与失败

触发线按模型窗口算：窗口减输出预留减系统提示余量，再取保守上限；网关报回的 input_tokens 作为水位下界。
自动压缩连着失败三次就停掉自动压缩（桌面端 `MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES` 同口径），
并把这件事告诉用户——每轮重试一次必然还是同样的失败，只会白烧全文请求。
手动 `/compact` 与 v4 compact 命令不受熔断影响。

压缩失败或被中断：摘要不应用、覆盖水位不动、时间线不删，失败原因可读。
压缩成功后摘要替换历史前部并推进覆盖水位；保留区为空时水位落到最后一段被压掉的行。
完整历史仍超过模型预算时，本轮模型请求明确失败（`mobile.context.overflow`），
不截短历史、不省略历史。

## 验收

端侧对话自检（`mobile-runtime/build/chat-smoke.mjs`）覆盖：手动与自动压缩接线、
分段摘要的滚动前缀与"整段早期历史都被覆盖"、摘要顶替历史前部、
自动压缩连败三次后不再重试且如实告知、上下文超预算时的失败口径与错误码。
