# 移动端 MCP 连接与工具执行

MCP 连接、工具清单和配置版本由同一份移动运行时拥有，按 `workspaceIdentity?.trim() || workspacePath` 隔离；设置页和 Agent 通过该运行时查看状态、使用配置和关闭旧连接。用户级及工作区配置读取沿用既有 MCP 配置服务，工作区同名配置优先；读取失败必须显示原因，不把失败当作空配置。更新、删除或禁用后，旧连接与工具立即失效，下一轮重新发现。

设置页传入 `mcpServers` 时，`connect` 使用这些参数进行真实连接测试，不写入配置，并将测试连接与 Agent 的目录配置连接分开；测试列表为空时关闭当前工作区的测试连接。`status` 仅读取此前的测试状态，允许传入名称子集，不重连、不替换其余连接。保存配置时两个连接域一并失效；测试用凭据不得进入错误或诊断日志。

本阶段支持远程 Streamable HTTP MCP（HTTP(S)，JSON 或会结束的 SSE 响应），复用 MCP 官方客户端进行协议协商、初始化、分页列举和工具调用。Android 使用原生后台 HTTP 桥，未接原生桥的环境使用标准 fetch；长连接 SSE、独立 SSE、stdio 与 MCP OAuth 在对应双向流或授权链完成前显示明确不可用，不能标记已连接或伪造工具。用户提供的 HTTP headers 可以传到同源服务器；禁止覆盖协议管理头。原生 MCP 请求禁止跨源重定向，Web fetch 回退禁止重定向，防止任意自定义认证头泄漏；执行失败不得向日志或状态泄漏 URL、凭据和请求头。

发现成功后，工具以 `mcp__服务器名__工具名` 声明给模型；名称冲突必须报错，不覆盖内建工具。调用必须经过 Agent 的权限流程，计划模式默认拒绝 MCP 副作用；用户取消与超时要传到客户端和原生 HTTP 任务。服务端返回错误需以工具错误返回，不能伪造成功；不支持的图片或音频以明确占位说明，文本和结构化结果保留。

```text
设置页写配置 → 同一运行时失效旧连接 → 下一轮刷新并连接当前工作区
                        → tools/list → 模型工具声明 → 权限闸 → tools/call → 结果
```

验收使用本地 MCP 测试服务器：握手、协议协商、带 header 的真实调用、分页、server 错误、超时和取消；两工作区隔离、配置切换后旧工具不可用、特殊名称冲突、不可用协议返回明确状态；通过伪原生桥覆盖跨源 HTTP 和阻塞等待释放，确认密钥不进入诊断。
